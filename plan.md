Website Portfolio Plan
Dian Raisa Gumilar
Konsep: Muted Green Tech Portfolio | Status: Planning
Tujuan: Personal portfolio untuk personal branding, pencarian kerja, dan dokumentasi proyek.
1. Ringkasan Konsep
Website personal yang informatif, mudah dinavigasi, dan memiliki karakter visual modern. Struktur informasinya sederhana, dengan interaksi ringan agar tampilannya tidak monoton.
Prinsip desain
•	Clean, user-friendly, dan responsif.
•	Personal dan profesional, dengan sentuhan Gen Z yang tidak berlebihan.
•	Fokus pada proyek, kontribusi, dan bukti hasil kerja.
•	Interaksi ringan, bukan animasi kompleks.
•	Mudah diperbarui tanpa harus mengubah banyak kode.
Referensi utama
•	Aakash Rajbanshi: acuan untuk layout sederhana dan informasi yang mudah dipindai.
•	Supratik B: acuan untuk interaksi ringan dan detail visual yang membuat website terasa hidup.
•	Gunakan referensi sebagai inspirasi, bukan menyalin desain secara langsung.
2. Tujuan dan Target Pengunjung
Tujuan website
1.	Memperkenalkan Dian sebagai fresh graduate Informatika.

4.	Menampilkan pengalaman, keterampilan, sertifikasi, dan prestasi.

Target pengunjung

•	Hiring manager untuk posisi AI/ML, software, atau mobile.
•	Developer yang ingin melihat source code dan implementasi proyek.
•	Dosen, kolaborator, atau komunitas teknologi.
Kesan yang ingin dibangun: fresh graduate Informatika dengan pengalaman proyek praktis, minat pada AI dan Machine Learning, serta kemampuan menjelaskan proses dan hasil pekerjaan dengan jelas.

8. Interaksi dan Animasi
Fitur utama
15.	Smooth scrolling pada navigasi.
16.	Filter proyek berdasarkan kategori.
17.	Hover effect ringan pada kartu dan tombol.
18.	Scroll reveal sederhana untuk section.
19.	Tombol salin email jika diperlukan.
Aturan interaksi
•	Semua fungsi penting tetap bisa diakses tanpa hover.
•	Hormati preferensi prefers-reduced-motion.
•	Jangan menambahkan animasi yang menghalangi pembacaan.
•	Pastikan tombol memiliki status hover, focus, dan active.
•	Jangan membuat animasi menjadi alasan lambatnya halaman.
Fitur opsional setelah versi utama selesai: dark mode, blog atau catatan teknis, serta halaman khusus publikasi atau penelitian.
9. Teknologi yang Disarankan
Bagian	Rekomendasi
Framework	React + Vite
Bahasa	TypeScript, jika nyaman digunakan
Styling	Tailwind CSS
Animasi	CSS transitions terlebih dahulu. Tambahkan library hanya jika diperlukan.
Ikon	Lucide
Hosting	Vercel atau layanan static hosting yang mendukung build Vite
Konten proyek	Data terstruktur di file lokal agar mudah diperbarui

Prinsip teknis
•	Jangan hardcode konten proyek berulang di banyak komponen.
•	Pisahkan data proyek dari komponen tampilan.
•	Gunakan komponen yang dapat digunakan ulang.
•	Simpan gambar dalam ukuran yang sesuai untuk web.
•	Jangan menambahkan backend atau database jika belum ada kebutuhan.
•	Pastikan website tetap berfungsi jika animasi dinonaktifkan.

10. Responsiveness dan Aksesibilitas
Desktop
•	Hero menggunakan layout dua kolom jika foto atau visual digunakan.
•	Kartu proyek menggunakan dua kolom.
•	Navbar horizontal.
•	Lebar konten dibatasi agar teks tidak terlalu panjang.
Tablet
•	Pertahankan dua kolom jika ruang cukup.
•	Kurangi ukuran heading dan jarak antarelemen secara proporsional.
Mobile
•	Semua section tersusun satu kolom.
•	Navigasi menggunakan menu ringkas.
•	Tombol cukup besar untuk disentuh.
•	Teks tidak terlalu kecil.
•	Gambar tidak terpotong hingga menghilangkan informasi penting.
Aksesibilitas dasar
•	Pastikan kontras teks dan background memadai.
•	Gunakan heading secara berurutan.
•	Beri alt text pada gambar informatif.
•	Semua kontrol dapat diakses menggunakan keyboard.
•	Gunakan indikator focus yang terlihat.
•	Jangan mengandalkan warna saja untuk menunjukkan status.
11. SEO, Performa, dan Keamanan
SEO
•	Judul halaman mencantumkan nama dan fokus profesional.
•	Tambahkan meta description yang ringkas.
•	Gunakan URL halaman proyek yang mudah dibaca.
•	Tambahkan Open Graph metadata agar tautan terlihat baik saat dibagikan.
•	Gunakan teks alternatif pada gambar.
Performa
•	Kompres gambar sebelum diunggah.
•	Gunakan WebP atau AVIF jika sesuai.
•	Hindari video autoplay dan background animasi berat.
•	Muat gambar proyek yang berada jauh di bawah halaman secara lazy-load.
•	Periksa performa dengan Lighthouse sebelum publikasi.
Keamanan dan privasi
•	Jangan menampilkan nomor identitas mahasiswa atau informasi pribadi yang tidak diperlukan.
•	Jangan memasukkan API key atau credential ke repository publik.
•	Periksa isi repository sebelum menjadikannya publik.
•	Pastikan file resume yang ditampilkan memang versi final.
